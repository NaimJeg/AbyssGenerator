# Abyss Generator 三维区块实施方案

基线日期：2026-10-29。目标平台：Minecraft 26.1.2、NeoForge 26.1.2.124、Java 25。

本项目在各维度原有的有限高度范围内实现通用三维体素区块：按 X/Y/Z 加载、生成、模拟、保存和同步，再评估扩大高度。主世界、下界、末地和模组维度均属于目标范围，专用维度只是验证环境。取消 ±4 亿作为产品目标；原版横向约三千万也不作为新的纵向承诺。ChunkCutter 仅用于理解问题与设计取舍，不复制其源码、网络协议或存档格式。

## 修订后的范围与实施顺序

本节替代下文早期版本的单维度首版范围和阶段工作量估计。下文 P0–P7 的数据所有权、线程、持久化及验收约束继续适用；其中固定维度和固定高度仅指测试夹具。首版仅支持新存档，不实施旧存档迁移，不自动将已有世界切换到未完成的稀疏格式。

- 最终目标：任意原版或第三方生成器无需修改即可透明三维化。整列生成后拆分不算按需三维生成；未经验证的生成器不能被宣称已兼容。
- P0：保留现有工具；以世界实例和维度实际高度建立服务边界，新增维度无关的单 section 生成接口与明确的生成能力分类。门格海绵作为原生三维生成的参考实现，不代替原版生成器兼容验收。
- P1：先验证生成管线接管与服务端所有权。分别审查噪声、生物群系、地表、雕刻、结构和装饰阶段的依赖，记录一个 section 请求产生的实际工作范围。消除未知区域当空气、整列包覆盖和主线程同步等待；不通过则继续调整接入，不扩大稀疏开关。
- P2：每维度独立版本化 page 存储，记录世界格式及生成器身份；保存 revision、已生成空气、损坏恢复和正常关闭均需闭环。禁止同时让原版列存储成为方块数据权威。
- P3：接入有界生成调度，先以原生接口验证取消、去重和确定性，再实现原版及第三方管线的透明接管。依赖整列的生成器必须明确报告限制，不偷偷使用整列回退冒充完成。
- P4：所有维度共用三维观看、模拟、传送和出生票据；登录、重生、传送门和维度切换均需就绪保护。
- P5：统一 section 协议、客户端缓存和垂直渲染窗口，覆盖主世界、下界、末地以及模组维度，保留必要的原版实体和附件生命周期。
- P6：完成方块光、天空光、流体、计划和随机 tick、实体、方块实体、POI、高度图及 NeoForge 事件。无天空光夹具通过不代表主世界兼容；自然刷怪、村民和跨区块结构纳入通用维度验收。
- P7：真实双客户端、冷生成/热读取、重启、故障恢复、十分钟垂直移动及生产 JAR 验收；测量工作量是否随活动 section 而非总高度增长。第三方生成器使用明确版本和样本矩阵，不能以有限样本证明任意实现都兼容。

当前状态：分形整列生成已验收；历史 P1 门槛仍失败，P2–P7 尚未完成。生产生成层开始提供单 section 契约；该契约是原生生成入口，不等于任意第三方生成器的透明适配，也不代表运行时已经按 Y 加载。

实施范围包括 `src/main`、必要的构建配置、测试源码、测试资源及验收脚本；允许补充保存竞争、协议乱序、取消和双客户端验证。此项依据本轮用户确认替代此前“不修改测试和验收脚本”的限制。

首轮交付矩阵为门格生成器及原版主世界、下界、末地。原版适配要求相同种子与原版生成结果一致，包含地表、结构及装饰；整列结果只可作为测试对照，不可成为运行时回退。第三方生成器仍是最终目标，后续按明确模组版本逐项验收，首轮不宣称任意生成器兼容。

### P1 接入进展（2026-10-29）

- 新增 `SectionManager.prepareSection(key, timeout)` 管理入口，使用独立非持久票据异步准备原版列；普通游戏访问不得调用旧同步 `ensureSection`。它不是按 section 生成，也不会扩大稀疏桥接启用范围。
- 请求在每世界主线程去重，最多 256 个待处理 section；同列共享票据。超时、取消、关闭时释放请求和票据，旧回调不能安装到重试请求。同一 key 的重复调用共享首个请求的截止时间；显式取消针对整个管理请求。
- `readySection` 是不触发加载的就绪查询，缺失与生成后空气可区分；这尚未修复原版方块读取接口的未知语义。管理请求完成后释放临时票据，不承诺数据继续驻留，持续使用者仍需后续 P4 票据。
- 可选 `abyssgenerator.generationAudit` 按世界统计原版生成阶段调用、输入 section 范围、耗时和失败。只有桥接开发运行默认开启；输入槽位总数不等于实际体素计算量，阶段耗时包含异步等待。
- 新增隔离运行脚本 `scripts/acceptance/Run-Bridge.ps1`，验证桥接及异步准备，并保留 P1 完整门槛的失败退出。生成差异实验使用脱离真实世界的临时 ProtoChunk，不安装、不保存实验地形。

当前 P1 仍未通过：原版生成依赖图、未知读取及整列网络包所有权尚未接管。依照既定阶段门槛，尚未进入 P2–P7，不将异步列加载作为三维生成完成。

后续生成接入实现增加了 `SectionSurfaceBuilder`：复用原版地表规则，只写入目标 section，
并使用原始世界高度、地表高度、跨边界石层深度和水面上下文。恶地柱和冰山扩展复用原版算法，
冰山的边界读取保留地表规则输出与随机数消费顺序。上下文可来自不可变游程摘要，或独立的无结构噪声采样器。
该采样器每次缓存一个 X/Z 位置、一个纵向噪声单元的数据，不从测试对照列取值；缓存限于任务生命周期。

原版恒定地表规则在没有特殊扩展生物群系时可跳过；主世界仅在规则树与原版完全相同、
整个目标 section 均位于初步地表以下且上方边界证明扩展无法进入时，才使用不依赖全高扫描的深层路径。
其它情况保留真实依赖采样并报告其成本，不将有条件优化宣称为全维度工作量保证。

差异验收包含完整上下文对照和独立采样两条路径。此前主世界 2293 处、下界 4499 处差异在已测样本中消除，
但结构地形适配、雕刻、装饰及运行时桥接尚未接通。不能因此将生成能力分类提升为完整原生 section 兼容。

本文中的类名和接口为待实现设计；“现状”及构建记录是已检查结果。本文不表示三维区块功能已经实现。

## 原始测试里程碑范围（产品范围以上方修订为准）

第一版开发基线采用专用测试维度 `abyssgenerator:abyss`，Y 范围为 **[-2032, 2032)**，共 4064 格、254 个 section。维度类型的 `min_y=-2032`、`height=4064`、`logical_height=4064`。这是当前目标版本 `DimensionType` 校验允许的范围，且落在原版 BlockPos 的 12 位有符号 Y 编码内。

选择此范围是为了先完成三维区块闭环，不是最终高度上限。维度高度可配置不等于任意修改现有存档：第一版由维度数据固定范围，配置只控制加载与调度；将范围和格式版本写入存档元数据。

第一版必须具备：

- 玩家上下移动时，只生成、模拟和同步附近的 section。
- 地形按目标 section 生成，加载代价不随世界总高度线性增长。
- 重启后保留方块修改、全空气 section、方块实体和已支持的计划 tick。
- 客户端只为可见高度窗口分配渲染 section，支持两名玩家在不同高度活动。
- 主世界及其他未启用维度保持原版行为；专用服务器不加载客户端类。

早期测试里程碑使用无天空光的测试维度及简单确定性地形。修订后，原版维度、第三方生成器、原版大型结构和天空光属于产品目标，必须分别验收；旧存档转换和渲染优化模组兼容仍不在首版范围。不能通过关闭天空光和结构宣称全维度兼容。

## 核心架构

### section 是运行单位 page 是组织单位

section 固定为 16×16×16；page 沿用 256 格高，表示同一 `(chunkX, chunkZ)` 下 16 个 section 的组织与存储分组。申请一个 page 不得默认生成全部 16 个 section。

```text
玩家与强制加载请求
        ↓
SectionTicketManager → SectionScheduler
                             ↓
                   SectionRepository 读取
                             ↓ 不存在
                   SectionTerrainGenerator
                             ↓ 主线程安装
          SectionManager 持有唯一可变 section
               ├─ 原版区块兼容接口
               ├─ 模拟 光照 实体
               └─ 玩家订阅 → section 数据包 → 客户端缓存与渲染
```

建议包结构：

```text
cc.sighs.abyssgenerator
  world/coord/       SectionKey PageKey VerticalRange
  world/section/     SectionRecord SectionManager SectionLifecycle
  world/ticket/      SectionTicketManager SectionInterest
  world/generation/  SectionTerrainGenerator SectionScheduler
  world/storage/     SectionRepository PageFileStore WorldFormat
  world/bridge/      VanillaColumnBridge
  network/           SectionSnapshotPayload SectionUnloadPayload
  client/            ClientSectionCache VerticalRenderWindow
  mixin/             服务端和通用接入
  client/mixin/      客户端接入
```

坐标键先用不可变 record 表示，不改写全局 `BlockPos.asLong()`。每维度持有自己的 map；跨维度索引必须显式包含维度键。page/localY 使用 `floorDiv`、`floorMod`，边缘 page 只接受处于维度范围内的 section。

### 数据所有权与原版接口

`SectionManager` 是已加载方块数据的唯一所有者。原版 `LevelChunk` 兼容视图引用同一份可变 section，禁止维护两个可能分叉的副本。

首版允许每个已加载区块列保留 254 项的 section 引用数组，以降低接入成本；它不允许为这 254 项全部创建独立方块容器、生成任务或 tick 数据。`ChunkAccess` 构造和空 section 填充路径必须一起审查。只优化自己的 map 而让原版构造器继续分配所有实际 section，不算通过。

共享空 section 只能作为不可变读视图。所有写入路径必须先取得独占 section，不能让一次修改污染其他空位置。未知、未生成和“已生成且为空”必须分开表示。

常规游戏读访问不得在服务器主线程等待工作线程生成。通过玩家/模拟票据预加载活动范围；对于尚未就绪的可交互范围，限制玩家进入或推迟操作，不能把未知数据当空气允许玩家坠落。显式管理命令和受控世界初始化可以使用单独的等待接口及超时。

原版列接口的完整兼容是实际技术风险。P1 必须验证读写、发包、保存是否能够被可靠接管；无法接管时停止继续铺设客户端和地形模块，先调整桥接设计。

### 状态与线程

```text
ABSENT → LOADING → GENERATING（磁盘不存在时）→ READY
READY → DIRTY → SAVING → READY
READY/DIRTY → EVICT_PENDING → 已保存并脱离世界 → ABSENT
任意异步阶段失败 → FAILED（保留错误原因并有限重试）
```

状态与 dirty 修订号分开维护：保存开始记录 revision；保存完成后只有 revision 未改变才能清除 dirty。保存期间发生新写入必须再次保存。空 section 也有持久记录，不能把清空后“不写文件”当作删除。

主线程负责安装、方块实体和普通实体生命周期、票据变更、世界可变数据操作。I/O 线程只读写不可变快照；生成线程只使用种子、参数和自有缓冲区，不直接操作 `ServerLevel`、POI 或活实体。

每次加载有 generation/token，异步结果安装前检查世界是否仍在运行、请求是否仍有效，防止卸载或换维度后旧任务重新安装。关闭时停止接收任务、等待有界收尾、flush 脏数据、报告失败，最后关闭 executor。

### 生成与边界

`SectionTerrainGenerator.generate(seed, sectionKey, settings)` 返回方块、生物群系和生成元数据。首版用坐标决定的分层岩石与洞穴函数，不能读取“邻居目前是否加载”决定地形。

后续噪声需要插值边界时读取一圈采样边界，不生成整列作为依赖。相同种子和坐标在不同加载顺序、不同线程数下应产生相同结果。结构跨 section 写入另设区域任务和提交规则，不能直接从生成线程写邻居世界。

### 保存和网络

独立存档建议放在该维度存储目录的 `abyssgenerator/pages/` 下，首版每个 `(chunkX,pageY,chunkZ)` 一个带版本的文件。先保证正确性，后续根据文件数量与 I/O 测量改成区域文件，不能在同一次改动中同时更换布局与数据语义。

每页至少存储格式版本、坐标、生成器版本、各 section 的存在状态、方块与生物群系 palette、方块实体、计划 tick。普通实体在 P6 接入独立持久化；光照是否落盘由 P6 决定，若重算必须有完成状态。未知格式不能按空世界继续运行；不支持的版本应拒绝加载并保留原文件。

原子替换写入采用同目录临时文件、flush 后替换；原子移动不支持时明确报错或采用经过恢复测试的备份流程。单页写入串行化，合并更新必须保留同页未加载 section。

新增自己的协议：维度、section 坐标、订阅 epoch、revision、数据体。首版只传完整快照和卸载通知，后续再加增量。客户端丢弃旧 epoch 或旧 revision；限制单包大小、条目数和每 tick 发送量。NeoForge 注册入口采用 `RegisterPayloadHandlersEvent` 与客户端 handler 注册事件，handler 切到正确线程安装。

原版完整列数据包与自定义 section 快照的所有权必须明确：启用维度由桥接层阻止旧整列方块数据覆盖新快照，同时保留必要的区块、实体及 NeoForge 附件生命周期。不能简单取消所有原版包。

### P0 基线与测试

- 修改 `ModConfig`：初始测试参数水平半径 4 section、垂直半径 4、模拟半径 2、保留裕量 1、卸载延迟 40 tick。它们是起始参数，P7 测量后调整。
- 新增维度类型和维度资源，先使用简单测试生成器或受限测试夹具；实际目标地形由 P3 接管。创建新测试世界，不修改现有开发存档。
- 客户端开发运行配置也启用 wideytest；移除失效的 verticalNoiseProbe 设置，修正 Java 版本注释中的 26.2 文案。
- 将数学函数及单测放入 `world/coord` 和 `CoordinateMathTest`。保留 ±4 亿只作纯数学边界用例时，必须标明与世界支持范围无关。
- 更新 WideY 命令：显示真实世界范围；增加权限、超范围明确失败、空气校验、加载统计以及延迟位置校验。
- 增加 `verifyAir`、`stats`、显式 `ensure` 命令；文档后续命令依赖这些新增功能，当前尚不存在。

验收：生产 main 不依赖 test；JUnit 真正发现并执行测试；两种开发运行均能注册命令；未启用维度行为不变。测试维度高度边界正确，越界写入返回清晰失败且不落盘。

### P1 服务端接入验证

新增 `SectionRecord`、`SectionManager`、`VanillaColumnBridge`。先在单列人工安装一个 section，接通 `ServerLevel/Level` 方块读写、`ChunkAccess/LevelChunk` section 查询及写入分配。审查构造器空 section 初始化、原版列保存、原版网络快照和高度图读路径。

高度图第一版扫描每列已加载且有效的 section，并标明未知区间；在测试维度中禁用依赖完整地表高度的出生点搜索，使用指定且预加载的出生平台。不能把不完整的高度图当成整个世界真实表面用于刷怪和天空光。

验收：在 Y=-1024、0、1024 分别读写不同标记，互不覆盖；空 section 写入后其他空位置不改变；创建一列不会物化 254 个独立数据 section。未就绪的修改被推迟或明确拒绝，不静默丢失。专用服务器启动成功。

失败门槛：若原版强制整列生成、全量数组物化或不可控整列覆盖仍存在，P1 未完成，不进入 P2。

### P2 保存与恢复

新增 `WorldFormat`、`SectionRepository`、`PageFileStore`。接入周期保存、保存命令和服务器关闭；禁止原版列保存成为同一方块数据的第二权威来源。第一步可保存纯方块 section，P6 扩展其他状态并增加格式兼容测试。

验收：写入 → flush → 正常停服 → 重启 → 验证；清空 → 保存 → 重启 → 仍为空；同页只加载一个 section 再保存，不丢其他 section；保存期间新修改不丢失。模拟损坏文件与写入失败，错误能定位到维度和页坐标，且不以新生成结果覆盖损坏数据。

### P3 按需地形

实现简单生成器及固定大小工作线程池，任务去重、队列有界、取消后不安装。初始并发建议 `min(4,max(1,CPU核数-2))`，队列上限 256；主线程每 tick 安装预算起始 2ms，允许单个任务超出预算但需统计，不能声称这是硬实时上限。

验收：申请一个 section 不触发整列生成；相邻 section 接缝连续；负 Y 正确；乱序生成与顺序生成哈希一致；退订后积压可清理；重启后从磁盘读取优先于重新生成。

### P4 三维加载与模拟票据

按玩家位置计算水平与垂直范围的集合差。观看、模拟、临时写入、传送准备和出生点票据分开建模。所有玩家的需求取并集，以引用计数或等价集合所有权避免一人离开导致另一人的 section 被卸载。首版采用方盒范围，便于精确验证和估算容量。

验收：静止玩家不逐 tick 重建完整任务队列；上下跨 section 更新正确；跨维度清除旧订阅；两人同列不同高度互不干扰；卸载先保存再释放。传送目标就绪后才恢复交互，不无限同步等待。

### P5 客户端同步与渲染

新增快照与卸载 payload、`ClientSectionCache`、`VerticalRenderWindow`。以 26.1.2 的 `ViewArea`、`SectionRenderDispatcher`、`SectionOcclusionGraph`、`ClientChunkCache` 为基准审查接入点，不引用 26.2 新类型。

渲染窗口的 Y 索引改为相对窗口底部，窗口随相机跨 section 移动并复用槽位。复用时清理旧 mesh、取消旧编译任务并验证坐标 token，随后更新遮挡图。窗口在顶底边界裁剪，不能按模运算把世界顶部接到底部。

验收：同一 X/Z 不同 Y 的方块显示正确；快速升降不出现旧高度 mesh；进入与退出 section 都使邻居边界重新编译；断线重连、跨维度和快照/卸载乱序不出现幽灵方块。实体、方块实体可见性与区块同步不脱节。

### P6 世界行为与 NeoForge 生命周期

逐项完成以下闭环，不能只验证静态方块：

| 子系统 | 实施重点 | 验收场景 |
| --- | --- | --- |
| 方块光 | section 装卸、边界传播、队列坐标和失效 | 火把放置与移除跨 section 正确 |
| 天空光 | 首版维度关闭；后续独立设计未知上方遮挡与天空可达性 | 开启前单独通过竖井与屋顶测试 |
| 计划 tick | section 保存、卸载暂停与恢复、重复调度去重 | 水和红石跨边界，重启后继续 |
| 随机 tick | 只在模拟范围执行，检查原版循环是否仍遍历全高 | 作物范围外暂停、返回后恢复 |
| 方块实体 | 安装、tick、卸载、保存、NeoForge 附件与能力失效 | 箱子内容、熔炉进度重启不丢失 |
| 普通实体 | 跨 section 转移、订阅、保存唯一性 | 掉落物与生物往返边界不重复、不消失 |
| POI 与高度图 | 定义权威数据与未知状态，不能由未加载空气推导 | 无完整实现前不开放依赖它们的自然刷怪与村民玩法 |
| 原版及 NeoForge 钩子 | 保留保存、实体、方块更新事件及附件生命周期 | 测试附件保存与关键事件恰好触发一次 |

首个可玩版本可以明确限制自然刷怪、村民和天空光，但必须完成玩家、物品、基础方块实体、流体及已支持方块 tick 的基本行为。不得把上述受限原型描述为完整原版生存兼容。

### P7 性能与发布检查

固定种子、相同 JVM 参数、同一硬件、固定移动路线，分别记录冷生成与热读取。初始水平/垂直半径都为 4 时，一名玩家的观看集合最多 `(2×4+1)^3=729` 个 section；保留、模拟、出生点和在途任务另计并分别显示，不能把 729 当总上限。

至少记录：各状态 section 数、实际方块容器数、渲染槽位数、生成/读取延迟、保存失败、队列长度、每 tick 安装耗时、发送字节、服务器 MSPT 和客户端帧时间。内存测量区分兼容列引用数组与真实 section 数据。

验收：相同视距在不同 Y 的驻留量相近；连续上下往返十分钟，任务数和内存没有持续单调增长；预热且静止后的服务器 p95 MSPT 低于 50ms；生成和发送队列均有上限。原版维度性能作对照，记录硬件与实测值，不预先承诺固定 FPS。

## 本地验收操作

以下开发命令在 P0 补齐工具、测试维度建成后执行；本轮文档编写没有执行这些游戏内操作。

```powershell
.\gradlew.bat compileJava compileTestJava test --console=plain
.\gradlew.bat build --console=plain
.\gradlew.bat runServer --console=plain
```

专用服务器使用单独测试存档；首次运行按正常方式处理 EULA。客户端用 `runClient`，确认开发运行启用测试属性。在目标维度执行命令，例如：

```text
/execute in abyssgenerator:abyss run wideytest info
/wideytest selfcheck
/execute in abyssgenerator:abyss run wideytest write -1024
/execute in abyssgenerator:abyss run wideytest save
```

正常停服并重启，在同维度执行 `verify -1024`；再执行 `clear -1024`、`verifyAir -1024`、`save`，再次重启并执行 `verifyAir -1024`。以上命令均带相同维度前缀，或玩家先进入该维度。

功能矩阵至少包含 Y：`-2032,-2031,-1024,-257,-256,-255,-17,-16,-1,0,15,16,255,256,257,1024,2031`。`-2033` 和 `2032` 为越界拒绝用例。`±2048`、`4096` 等只作坐标编码诊断，不混入第一版可放置方块断言。

新增自动测试至少覆盖坐标、状态转换、保存 revision 竞争、空页恢复、协议过期快照拒绝、确定性生成。手动测试补齐真实双客户端、传送、mesh 和流体场景。无 JUnit 用例时不能以构建成功替代阶段验收。

## 扩大高度的后续门槛

P7 达标后再提出新范围，先评估约 ±8192，再决定是否需要约 ±32768；这些数值是评估档位，不是本轮承诺。扩大高度必须解决原版 BlockPos 的 12 位 Y 打包，而不仅是放宽 DimensionType 校验。

如果继续保留横向约 ±三千万，X/Z 各需要 26 位，64 位整数只剩 12 位给 Y。不能直接把 Y 位数加大而声称横向兼容不变。下一轮需对网络 BlockPos、方块实体、POI、计划 tick、光照键、地图缓存及第三方扩展逐项选择显式坐标或局部坐标表示，禁止只改 `asLong/getY`。

扩展前还应移除随总高度增长的区块兼容数组和全高遍历；评估渲染及物理运算的局部坐标需求。最终范围由行为矩阵与资源测量决定。只要有限高度版本已经证明三维加载收益，就不需要为宣传高度而扩大实现面。

## 开始实施时的首个提交

首个代码提交仅做 P0：补配置与坐标单测，修正 WideY 工具和开发运行开关，新增专用维度测试夹具，清理失效探针。第二个提交专门完成 P1 的单 section 服务端接入验证。P1 的结果决定后续是否沿用当前桥接方案。

后续提交不得混入 `docs/chunkcutter-reversed` 的源码或 JAR；参考目录不是构建依赖，也不是待迁移代码目录。
