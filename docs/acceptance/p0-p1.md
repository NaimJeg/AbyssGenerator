# P0 baseline and P1 bridge acceptance

Historical stage record. The subsequent [fractal generator](fractal-worldgen.md)
replaces the production abyss dimension's flat fixture. The isolated P1 flat
fixture now lives at `abyssgenerator:bridge_fixture` in test resources; the
bridge scripts target that dimension. The failed P1 gate remains unresolved.

Date: 2026-10-29. Minecraft 26.1.2, NeoForge 26.1.2.124, Java 25.0.3.

**Overall result: incomplete. P1 has not passed. P2–P7 were not implemented.**
The implementation plan explicitly prohibits advancing beyond a failed P1 gate.
No claim of playable three-dimensional loading, custom page persistence,
section networking, or bounded vertical rendering is made by this record.

## Changes

- Added finite-range coordinate records, 23 discovered JUnit cases, scheduling
  configuration defaults, and the no-skylight `abyssgenerator:abyss` dimension.
  The dimension still uses an empty vanilla flat generator as a test fixture.
- Replaced the development command harness with permission-checked commands,
  explicit range rejection, non-loading probes, actual bounds/allocation
  statistics, verified clears, and delayed server teleport readback.
  `ensure` works only in the opt-in bridge; elsewhere it explicitly fails.
- Added isolated server/client Gradle runs and reproducible AutoJS scripts.
  AutoJS runs with its supported standalone Rhino backend. The optional pinned
  KubeJS dependency failed server startup with
  `NoClassDefFoundError: dev/latvian/mods/betteradvancedtooltips/BATIcons`.
- Added an opt-in bridge at the `ChunkAccess` missing-section allocation call,
  immutable unknown views, a per-`ServerLevel` section manager, explicit write
  rejection, unload cleanup, and omission of unknown sections from vanilla
  save snapshots. Existing ready sections still use vanilla persistence.
- Normal runs leave the bridge disabled. The experimental run cancels travel
  into the dimension until player readiness protection exists.

## Failed P1 gate

`scripts/acceptance/bridge-gate.js` inspects a real
`ClientboundLevelChunkPacketData` and vanilla block read. With the three markers
installed it measured:

```json
{
  "passed": false,
  "columnPacketSections": 254,
  "columnPacketNonAirSections": 3,
  "columnPacketBytes": 8185,
  "unknownVanillaReadIsAir": true
}
```

The packet still contains all vertical slots and the prepared block data.
There is no implemented ownership boundary preventing it from overwriting a
future section snapshot. Unknown views also appear as air through vanilla
read APIs. Dimension-travel cancellation contains the prototype; it does not
implement gameplay readiness. The invocation tool writes the report and then
returns an error when the scenario's `passed` field is false.

Before proceeding to P2, the bridge needs a tested vanilla packet ownership
boundary, bounded readiness handling for player ingress and interaction, and
the planned unknown-heightmap semantics and preloaded spawn platform. The
controlled `ensureSection` currently uses synchronous vanilla column loading;
it is not a gameplay scheduling API and has no independent timeout yet.

Storage remains vanilla: there is no page format, revision-safe asynchronous
saving, format metadata, corruption recovery, or block-entity/tick page
serialization. No generation worker queue, player tickets, custom payloads,
client cache, rendering window, or P6 lifecycle integration exists. Config
values for those future subsystems are definitions, not evidence they run.

Two simultaneous clients, fluids, entities, attachments, performance soak,
fault injection, and a production-JAR-only runtime launch were not tested.

## Reproduction and evidence

Run the baseline suite with:

```powershell
.\scripts\acceptance\Run-Baseline.ps1
```

It refuses an occupied AutoJS port, builds the project, creates a new isolated
fixed-seed world, performs write/restart/clear/restart assertions, and normally
stops every server it launches. Reports are in
`build/acceptance/results/baseline-run/`. Failed startup or failed assertions
return errors; a successful script evaluation alone is insufficient.

For the sparse server fixture, configure `build/acceptance/bridge-server/server.properties`
with a new world name and server port 25568, then run:

```powershell
.\gradlew.bat runBridgeServer --console=plain
.\scripts\acceptance\Invoke-AutoJS.ps1 -Port 25588 -Script scripts/acceptance/bridge.js
.\scripts\acceptance\Invoke-AutoJS.ps1 -Port 25588 -Script scripts/acceptance/bridge-gate.js
```

The last command **must currently fail**. Do not reinterpret this as a pass.
`bridge-persistence.js` supports `verify`, `clear`, and `air` phases; run the
verify and air phases after full process restarts, without first running the
marker-writing `bridge.js`. Set `acceptancePhase` before evaluating the file.

For a real client, run `runAcceptanceClient`, evaluate `connect.js` on client
port 25587, set the test player to spectator, and transfer them to the baseline
dimension before running `Test-Client.ps1`. That script polls actual client
state with a deadline instead of treating a teleport request as success.

Raw local evidence is under `build/acceptance/results/`: `p0-integrated.json`,
`p0-client.json`, `p1-bridge-final.json`, `p1-restored-markers.json`,
`p1-restart-air.json`, and `p1-gate.json`. These build artifacts are ignored by
Git. Existing development saves and pre-existing Git changes were preserved.

## Follow-up: asynchronous preparation and generation feasibility

Date: 2026-10-29. This section records additional implementation; it does not
supersede the failed complete P1 gate above. Test sources and acceptance scripts
may now be extended, as explicitly confirmed for the P0–P7 implementation.

Implemented a main-thread-owned asynchronous administrative preparation API.
It uses a dedicated nonpersistent vanilla loading ticket, shared by requests in
the same column. Requests have a monotonic timeout, a 256-entry capacity,
deduplication and cancellation. Cancellation or world close releases resources;
late callbacks cannot install data or interfere with a replacement request.
Repeated requests preserve the existing owner record and deadline. The existing
synchronous `ensure` remains a controlled legacy test command only.

This API still loads a vanilla column and initializes only the empty flat bridge
fixture. It is neither the P3 terrain scheduler nor the P4 gameplay ticket system.
Completing preparation releases its temporary ticket; it does not promise continued
residency. `readySection` distinguishes absent data from generated air without
loading, but vanilla reads still do not have this distinction.

Added per-world, opt-in generation stage observations. Counts describe stage
invocations and input section slots, not actual voxel operations; cumulative
durations include asynchronous waiting and must not be read as CPU time.

## Follow-up: section surface context implementation

The earlier clipping counterexample is now a regression for a production surface
stage component. `SectionSurfaceBuilder` evaluates vanilla rules against the
original world bounds, cross-section solid/fluid metadata and authoritative
column heights, writing only the target section. It preserves the badlands and
iceberg algorithms; iceberg boundary reads evaluate surface-rule output where
needed, instead of silently substituting pre-surface stone for air/water.

Two context implementations are available: immutable coalesced material runs,
and task-local sampled profiles. `UnstructuredNoiseSurfaceContext` obtains its
samples independently using one X/Z column and one vertical noise cell at a time.
It does not read the full-column test oracle or live world chunks. It explicitly
excludes structure adaptation and is not registered as a complete world generator.
Its sample counter measures returned block positions, not all underlying density
function evaluations. Full-domain preliminary-surface noise caches and reference
slots still exist and must be included in future resource measurements.

The no-op shortcut checks both the exact constant rule and absence of extension
biomes. The deep-overworld shortcut checks structural equality with stock rules,
the preliminary-surface bound for every target column, and a non-air boundary
that prevents badlands filling into the target. It is applied to the whole target
section, avoiding mixed skipped/non-skipped columns with stale neighbor heights.
Other requests still sample their actual dependencies; their cost is not bounded
to a single section and the P1/P7 work-scaling requirement remains open.

Executed checks:

- Build and 43 JUnit tests passed. New randomized checks compare compressed and
  sampled depth counters against an independent descending scan across 200
  mixed solid/fluid/air columns, including negative Y and section boundaries.
- Twenty-one noise/surface cases cover three coordinates in all vanilla dimensions
  at seed 104729, an additional coordinate at seed 0, and fixed eroded-badlands,
  frozen-ocean and deep-frozen-ocean fixtures. Both oracle-context and independent
  context output matched the full-column reference, including fresh Y-section-0
  requests with an empty metadata cache.
- A separate low-ground badlands fixture exercised 10228 extension writes across
  section boundaries with zero mismatches. Frozen-ocean cases exercised actual
  iceberg writes (1306 in one fixture), rather than only selecting the biome.
- Native Menger checks still cover all 254 sections and palette isolation.
- Original sparse bridge and asynchronous preparation assertions still passed;
  the complete P1 gate still failed on generation takeover, unknown reads and
  vanilla packet ownership. No P2–P7 completion is claimed.

In the measured original-overworld sample at seed 104729, column `(-8,5)`, the cold
Y-section-0 metadata request fell from 86368 returned block samples to 864 while
remaining identical to the reference. The End's constant surface rule required
zero such samples. After retaining surface-hole height changes above the target,
the Nether example required 16352; these numbers are
component observations, not a performance acceptance or universal bound.

The final successful surface run is `bridge-20261029-102601-312`, including
`generation.json` (component checks passed) and `gate.json` (P1 failed). The
runtime bridge still invokes vanilla column generation; the new surface component
is exercised through the development harness, not normal gameplay. Structure
adaptation, carving, decoration, end-to-end readiness and networking remain required.

The ordinary-mode baseline was also rerun after introducing the access transformers:
all 17 markers survived restart and remained air after clear/save/restart. The
access transformers expose vanilla surface evaluation helpers; they do not inject
the new component into normal world generation. Production-JAR inspection verifies
